# 2D 技能特效创作工作流

Godot FX Atlas 的首页是特效搜索引擎与实现思路索引。Atlas 条目用于比较轮廓、运动、阶段、分层、收尾和 Godot 技术路线；采用前仍须核对原页许可、价格和版本，付费或受保护资源只复现可解释的表现逻辑，不复制原始美术。另设的资产贴图库只收录经过许可与安全审计、允许直接分发的位图，两者不能混为一谈。

## 1. 先建立效果合同

在检索或生成前写清：

- 触发：何时开始，是否允许取消。
- 锚点：施法者、目标、路径、地块、屏幕或世界位置。
- 语义：伤害、治疗、强化、减益、移动、召唤、范围预警等。
- 生命周期：瞬时、循环、持续状态或多阶段序列。
- 尺度与方向：首帧轮廓、主运动、落点和收尾。
- 预算：最大并发、粒子数、纹理尺寸、池化与降级方式。

缺少这些事实时，先补合同，不用“更多粒子、更亮、更炫”代替设计。

## 2. 用 Atlas 检索结构

从 #overview 进入，先按战斗机制和视觉标签筛选，再选 2–4 个分工明确的参考：

1. shape：低频剪影与尺度。
2. motion：唯一主运动与方向。
3. timing：准备、释放、命中、余韵和回收。
4. finish：消散、残留、循环接缝或命中停顿。

参考只提供结构证据。不要把一个资源包的贴图、场景、Shader 和独特构图整体照搬，也不要混入与技能语义无关的视觉层。

## 3. 图标与文字说明共同驱动

当消费项目已有技能图标和文字说明时，两者必须同时使用：

- 图标约束母题、低频剪影、主色和视觉重心。
- 文字说明约束触发、锚点、运动方向、目标、瞬时/持续与收尾。
- 图标不直接作为特效贴图播放；角色、场景、卡框、文字和 UI 构图不得进入特效主体。
- 编号、角色名、策划文本、私有素材路径和接入进度只保存在消费项目中，不写回 Atlas 或通用工具。

## 4. 优先复用已审计贴图

先在资产贴图库按效果原型、贴图族和合成层级检索。透明底版本优先作为灰度遮罩、粒子纹理或 Shader 输入；黑底版本只在明确的混合管线中使用。

- 贴图只承担 `shape` 或 `finish` 层，不把单张通用素材当成完整效果。
- 导出选材清单并保留来源、许可与文件哈希。
- 完整素材包保留在 Atlas，消费项目只复制实际使用的子集。
- 贴图库没有合适轮廓时，再进入离线生图或原创绘制流程。

## 5. 离线生图与素材质量

GPT 等图像模型只在离线制作阶段生成透明主体、遮罩、局部贴图或关键姿态；游戏运行时不得调用模型。

提示应明确真实透明 Alpha、效果主体、留白、主色、轮廓、用途和排除项。通用质量门槛：

- 压制颗粒、噪点、脏烟、随机闪粉和无意义碎屑。
- 使用受控渐变、克制辉光和干净可读的轮廓。
- 为保证深浅背景可读，可适度提高主体边缘不透明度，但不能形成硬白边或彩色毛边。
- 拒绝过饱和霓虹、塑料高光、模板化爆炸、伪 3D 图标、金属 UI 边框和廉价手游/页游质感。
- 拒绝文字、水印、角色、场景背景和卡框。
- 必须检查文件真实 Alpha；把棋盘格画进 RGB 或整张不透明的输出直接淘汰，不用运行时抠色补救。

每个生成候选记录提示、输入角色、输出哈希、Alpha 检查和拒绝原因，但不记录 API 密钥或临时绝对路径。

## 6. 序列帧与 Shader/程序层组合

### 导演、时序与图层语言

保留以下导演诊断作为反例参照：

> 现在的问题不在素材本身，而在导演、时序和图层语言。当前版本把“一张好素材”当作沿直线移动的贴片，再用几何圆环补命中，缺少预备—引潮—过场—落池—余韵的镜头节拍；主潮也只有整体透明度，没有局部溶解边界，所以会显得像 UI 动画。

素材质量不能替代演出设计。把“一张好素材”当作沿直线移动的贴片，再用几何圆环补命中，会缺少有意图的运动、阶段衔接与材质变化；主层若只有整体透明度变化、没有局部溶解边界，容易显得像 UI 动画。

先从导演视角写节拍表（beat sheet），再安排素材和技术。例如流体传输可采用“预备—引潮—过场—落池—余韵”；这是表现示例，不是所有技能必须套用的模板。逐段明确视觉主语、运动弧线、加减速、峰值、图层交叠和注意力交接。主层、承接层和残留层错峰出入；用局部 Alpha、遮罩流动与有机溶解交代材质的聚散，整体淡入淡出只控制总包络。圆环等几何形状仅在玩法范围或美术语言需要时使用，不作为默认命中补丁。

### 帧间连续性与曝光时序

序列帧制作应控制相邻帧的形变增量（frame-to-frame deformation），保持轮廓、体积、视觉重心、运动方向、纹理流向和 Alpha 边界的时间连续性（temporal coherence）。统一画幅、相机、pivot 与主体尺度；在形变剧烈的区间补充中间帧（in-betweens），不要把相距过远的关键姿态直接拼成动画。短序列只承载一段连续的原子形变，不能靠少量帧覆盖整段复杂演出。帧混合仅用于连续姿态的细微衔接，不能用重影掩盖轮廓跳变。

空间间距（spacing）与时间节奏（timing）分别设计。制作曝光表（exposure sheet），明确每帧或每段的持续时间、过渡窗口、关键姿态停留（hold）及结算峰值；按意图安排蓄势停留、释放加速、落点短停与余韵延长，不机械地给所有帧相同时间。若引擎使用固定帧率，以时间重映射或逐帧时长实现编排；仅提高 FPS 不能修复缺失的中间形变。

验收同时查看逐帧联系表、正常速度和慢放的 GPU 动态，核对跳帧、抖动、体积漂移、重影、亮度抽动、Alpha 突变与循环接缝。记录帧数、播放顺序、曝光时长和总时长；静态单帧美观不代表动画连续。

单张图不代表完整特效。推荐职责分层：

| 层 | 主要职责 |
| --- | --- |
| 短序列帧 | 关键形变、手绘姿态、命中峰值、可识别主体 |
| CanvasItem Shader | 呼吸、局部流动、遮罩、溶解、边缘与克制辉光 |
| Tween / 程序绘制 | 位移、缩放、旋转、拖尾、冲击波和曲线 |
| 粒子 | 少量方向性余韵、碎屑或状态提示 |
| 生命周期控制 | 预热、播放、循环、取消、回收和对象池复位 |

第一轮只做低频剪影、锚点、阶段和主运动；第二轮再加入中高频细节。关闭 Glow 后仍须读出形状和方向。GL Compatibility 方案不依赖屏幕纹理、计算着色器或无 fallback 的平台特性。

## 7. 专用预览与质量门禁

所有候选先进入专用 VFX Gallery，不直接接战斗。Gallery 至少支持：

- 组合播放与单层播放。
- 深色底、亮色底和参考网格。
- 速度、细节密度与缩放调节。
- 瞬时结束、循环接缝、取消、目标消失和回收。
- 多实例压力测试与截图回归。

headless 只证明资源、场景、Shader 和生命周期合同可加载。只有真实 GPU 画面通过人工检查后，候选才能从“已生成”进入“GPU 已验证”；再经明确批准后才能接入正式项目。

## 8. 交付清单

一个可审查的 VFX 交付至少包含：

- .tscn 固定视觉结构。
- .gdshader / .tres 材质与参数。
- .gd 生命周期、锚点、取消和回收逻辑。
- 原创透明纹理或短序列帧。
- 效果合同、参考链接与许可记录。
- 提示/生成记录、Alpha 检查、性能预算与 Gallery 截图。
- 无图、生成失败或 Compatibility 受限时的显式回退。

消费项目最终仍应按自己的事件、锚点、资源目录和测试合同接入；Atlas 不替代项目架构。
