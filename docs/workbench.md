# 特效预检工作台（FX Preflight Workbench）

> `workbench.html` · 项目无关 · 数据由使用方工程注入 · 数据包不进 git

---

## 1. 它解决什么问题

做特效的反馈闭环通常是：

```
写实现 → 进引擎 → 跑探针/截图 → 人看 → 不满意 → 改 → 再来一轮
```

**把最贵的媒介放在了最前面。** 一次试错的成本 = 一轮引擎往返（改数据 → 导入 → 渲染 → 截图 → 评审）。
方案本身还没定，就已经付出了这个代价，所以返修多、迭代慢。

工作台把**判断**挪到浏览器里，顺序改成：

| 步骤 | 在这个台子上做什么 | 过不了的判据 |
|---|---|---|
| **① 方案** | 看极性 / 锚点 / 唯一母题 / 唯一运动 / 目标色，以及合同字段有没有冻结 | 同极性内母题或色相撞车 |
| **② 选材** | 候选素材在**真实读数尺寸**上比对（原图 / 上色·浅底 / 上色·深底 / 2×） | 45px 上读不出母题 |
| **③ 摆位** | 载体几何叠加（卡面 / 棋格 / 锚点框 / 预算圈），滑块 + **画布拖动**调大小与偏移 | 超预算、糊到相邻格 |
| **④ 导出** | 下载决定 JSON，交回工程写实现 | 未点「确认」的条目不算认可 |

**人认可之后才进引擎。**

---

## 2. 为什么数据包不进 git（必读）

本仓库是**公开仓库**。数据包里有使用方工程的名称、条目命名、素材路径、参考截图 —— 属于私有内容，
**提交即公开**。所以：

- `project-data/` 与编译产物 `assets/workbench-data.js` 都在 `.gitignore` 里；
- 公开仓库里**只有工具，没有别人的工程数据**；
- 使用方工程引用本工作台时，也应当把「导出的数据包」纳入自己的忽略规则（若导出到自己的仓库内）。

---

## 3. 数据包契约

路径：`project-data/<bundle-id>/bundle.json`。**单文件自包含**（图片以 data URI 内嵌），
这样工作台不需要任何 Node 依赖、也不依赖使用方工程的目录结构。

```jsonc
{
  "schema": "fx-preflight-bundle/1",
  "bundle_id": "my-project",              // 必填，目录名建议一致
  "label": "我的项目 · 状态特效",           // 可选，下拉里显示
  "generated_at": "2026-01-01T00:00:00Z",
  "generator": "my-project/tools/export_preflight_bundle.py",

  // ── 载体几何：工作台的一切换算都靠它，必须与使用方引擎一致 ──
  "geometry": {
    "card":  { "width": 100, "height": 60, "radius": 10 },   // 必填：棋子/目标承载面（参考像素）
    "cell":  { "width": 132, "depth": 55 },                  // 可选：棋格/格子（没有就不画）
    "anchors": {                                             // 必填：[x,y,w,h] 归一化到 card
      "unit_head": [0.32, 0.08, 0.36, 0.24],
      "unit_body": [0.18, 0.22, 0.64, 0.58]
    },
    "display_k": { "frame_clip": 210, "sprite": 100 },        // 显示直径 = K × size（组件归一系数）
    "budget": { "mode": "cell_min_axis", "factor": 0.9 }      // 可选预算：见下表
  },

  "backgrounds": [                        // 可选；给「浅底/深底」两档对照
    { "id": "light", "label": "浅底", "color": "#e9dfc8" },
    { "id": "dark",  "label": "深底", "color": "#1b1720" }
  ],

  "items": [
    {
      "id": "S01",                        // 必填，唯一
      "name": "霜冻",
      "group": "负面状态",                 // 可选，左侧导航分组
      "note": "受到冰系伤害提高",
      "polarity": "debuff",               // buff | debuff | trigger | aura
      "anchor": "unit_body",              // 必须出现在 geometry.anchors 里
      "tint": [0.45, 0.72, 0.95],         // 目标色（工作台用它上色候选素材）
      "contract": {                        // 可选但强烈建议：冻结的「一条一条」合同
        "motif_id": "frost_crystal",
        "motif": "放射霜纹",
        "motion": "slow_pulse_crack",
        "motion_label": "缓慢脉动 + 低频崩点",
        "hue_family": "霜蓝",
        "motion_pair_note": ""
      },
      "impl": {                            // 可选：当前实现摘要（用于对照）
        "node_count": 5, "prim_id": "frame_clip", "display_px": 90,
        "loop": true, "offset": [0, 0]
      },
      "candidates": [
        {
          "id": "frost_crystal_v2",
          "label": "term_frost_crystal",
          "source": "generated",           // generated | current | reference | external | thirdparty
          "source_label": "自有生成",
          "note": "1024×1024 · 4×4 图集",
          "license": "internal",
          "path": "assets/fx/frost_crystal.png",
          "image": "data:image/png;base64,...",          // 必填：原图
          "image_tinted": "data:image/png;base64,...",   // 强烈建议：按 tint 上色后的版本
          "frame_cols": 4, "frame_rows": 4, "best_frame": 2,
          "aspect": 1.0
        }
      ]
    }
  ]
}
```

### `geometry.budget.mode` 可选值

| mode | 含义 | 需要的字段 |
|---|---|---|
| `cell_min_axis` | 格子的短边 × factor（默认 0.9）——**最常用的「不许糊出格」口径** | `cell` |
| `cell_width` | 格子宽 × factor | `cell` |
| `card_width` | 卡面宽 × factor（「包住棋子」的覆盖型常用） | `card` |
| `fixed` | 直接给像素 | `px` |
| `none` | 不判预算 | — |

## 4. ⚠️ 写导出器的三条硬要求（不满足，工作台会**骗人**）

这三条是实际踩出来的，写在契约里但不强制校验（校验不了），必须由导出器负责：

### 4.1 必须提供**上色版**（`image_tinted`）

很多特效素材是**「亮度实体」**：本体近白，靠运行时乘 tint 上色。
如果工作台只画原图，浅底卡面上会是**一片空白** —— 于是它显示「什么都没有」，
而实际上引擎里是有东西的。**工具一旦说谎，人就会被它误导。**

> 工作台因此把每个候选排成 4 格：`原图 · 上色/浅底 · 上色/深底 · 2×`。
> 原图那一格只用来读纹样结构，**判断可读性必须看上色版**。

### 4.2 序列帧必须给 `best_frame`，不要默认第 0 帧

实测：某图集首帧 alpha 覆盖率 **0.02**、第 10 帧 **0.136** —— 首帧是过渡/空帧。
取首帧会让工作台显示成空图。
**导出器应当扫描各帧的 alpha 覆盖率，取最高的那一帧作为 `best_frame`**，工作台默认就落在该帧。

### 4.3 缩略图要在**真实读数尺寸**上有意义

工作台会用 45px 那一列做判断（可在代码里按项目调整）。导出器给的缩略图分辨率不能太低，
否则 45px 上糊成一团，判不出来。**按「最长边 ≥ 144px」导出即可**（再大是浪费，工作台会缩放）。

## 5. 决定文件契约

工作台「④ 导出」下载的是：

```jsonc
{
  "schema": "fx-preflight-decisions/1",
  "bundle_id": "my-project",
  "decisions": {
    "S01": {
      "confirmed": true,            // 只有点过「确认本条采用此方案」才是 true
      "asset_path": "assets/fx/frost_crystal.png",
      "asset_label": "term_frost_crystal",
      "anchor": "unit_body",
      "display_px": 68.5,
      "anchor_offset": [0, -4],
      "alpha": 1
    }
  }
}
```

使用方工程的生成器读它时，**只应用 `confirmed: true` 的条目** —— 这是「人在环」的收口。

## 6. 导入流程

```bash
# 1) 在使用方工程里产出数据包（导出器由各工程自己写，见 §4 的三条硬要求）
python <your-project>/tools/export_preflight_bundle.py
#    → 写出 project-data/<bundle-id>/bundle.json

# 2) 回到本仓库编译数据包（会校验 schema，坏数据直接报错）
npm run build:workbench      # 只编译数据包
npm run build                # 站点构建（顺带编译数据包）

# 3) 起本地服务看
npm run dev                  # http://127.0.0.1:4173/workbench.html
```

> 为什么必须走本地服务：页面要 `fetch`/`import` 数据模块，`file://` 下会被浏览器拦。
> `npm run dev` 已经就绪（`scripts/serve.mjs`）。

没有数据包时，`npm run build` **照常成功**，页面显示导入指引 —— 公开仓库对其他人保持可用。

## 7. 外部素材库与命名规范

选材页底部有「外部素材库」面板：**选一次本地文件夹**，整个库就能在页面里按关键词搜，
搜到直接「加入候选」。全程在浏览器本地索引 —— **不上传**，也没有任何外部素材被写进本仓库。

面板上的列表分两部分：

- **索引**：来自数据包的 `external_library`（只有 `name` / `tag` / `title` / `dir`，**不带图**），
  用来在还没选文件夹时就知道「该找哪一张」；
- **图**：只有在选了文件夹、文件名对得上时才会显示缩略图，并出现「加入候选」。

### 命名规范（搜索的前提）

搜索**只认文件名**（外加索引里的 tag / title）。所以外部素材应当命名成：

```
<类别>_<三位序号>_<描述>.png
```

- **类别** = 机制或视觉类别，**中文**（能被中文搜索命中），如 `雷电能量`、`斩击刀光`、`法阵符文`、
  `冲击爆点`、`光效辉光`、`序列帧`；
- **序号** = 类别内顺序，保证唯一、可复现；
- **描述** = 来源标题转成的 ASCII slug（有意义的标题才有），能被**英文**搜索命中。

例：`雷电能量_007_blink-pink-white.png`、`斩击刀光_003.png`

于是「输中文找类别、输英文找描述」都能命中。

> **不要按像素去猜逐张描述。** 在缩略图上给 300 张图起描述名，起错的概率远高于起对的收益，
> 而**起错名比粗颗粒更糟**（搜到了但不对）。类别颗粒度来自已有标签，是可验证的；
> 需要更细就人工补一份覆盖表（见你所用工程的重命名工具）。

### 改了名之后

重命名会让「清单里的路径」和「磁盘上的文件」脱钩，而引擎是按清单加载的。所以顺序必须是：

1. 重命名（同时产出一份 `旧名 → 新名` 对照表，便于回滚）；
2. **让引擎重新导入** —— 否则资源导入缓存仍指向旧路径，表现为「资源不可加载」；
3. 校验「清单声明数 == 可加载数」，并且没有 `material_id` 冲突；
4. 重新导出数据包。

⚠️ **注意重复源**：一个库里常有「不同来源、同一张图」的重复项。改名后它们会塌到同一个文件名上，
造成「磁盘改对了、清单没同步」和 `material_id` 冲突。这一步必须有**自愈 + 全量断言**，
不能静默通过 —— 否则工作台会一半图正常、一半图点不动。

## 8. 交回工程：写回磁盘，不要下载文件

**「人在环」不该靠下载文件来交接。** 人设置完，还得下载一个 JSON、再告诉 AI"我设了什么"——
这既多余又容易错。所以 `npm run dev` 起的服务多了一组回写端点：

| 端点 | 作用 | 落盘位置 |
|---|---|---|
| `POST /__wb/state` | 当前设置（决定、当前条目、界面状态） | `project-data/<bundle-id>/workbench-state.json` |
| `POST /__wb/drawing` | 手绘图（PNG dataURL） | `project-data/<bundle-id>/drawings/<条目>.png` |
| `GET /__wb/ping` | 页面自检"服务在不在" | — |

* 工作台**每次改动都会自动写回**（去抖），打开页面时先写一次；
* 沙盒路径安全：只监听 `127.0.0.1`，只写 `project-data/` 之内，`bundle_id` 必须正好一段、
  相对路径最多四段，非法字符替换为 `_`；
* 状态文件用的是**和决定文件相同的 `fx-preflight-decisions/1` schema**（额外带 `drawings` 与 `ui`），
  所以使用方工程读哪个都行，不用写两套解析；
* 下载按钮仍在，作为**退路**（例如直接双击 HTML 打开、没起服务时，浏览器不允许写盘）。

> 端点逻辑被抽成可导出的纯函数（`writeWorkbenchPayload` / `safeUnderData` / `decodePngDataUrl`），
> 由 `tests/workbench-write.test.mjs` 覆盖 —— 包括路径穿越、非 PNG 负载、子目录未被拍平。
> **这套测试当场抓到过一个真 bug**：最初把 `/` 也当非法字符替换，`drawings/x.png` 被拍平成
> `drawings_x.png`，子目录凭空消失。

### 手绘参考（✏️ 页）

在生成素材**之前**，人心里往往已经有形状了。与其等生成出来再否掉，不如直接画一版：

* 画布用的是**和合成示意同一套载体几何**（卡面 / 棋格 / 锚点），所以笔画位置可直接对照；
* 底下垫一层**当前实现的淡显**，方便"照着我想要的改"；
* 工具：画笔 / 直线 / 橡皮 / 粗细 / 颜色（默认取该条目标色）/ 撤销 / 清空；
* 「写回磁盘」→ `drawings/<条目>.png`。

**语义要说清楚：手绘是"给生图的参考"，不是成品素材。** 它的去处是生图输入（例如作为参考图），
而不是直接进项目当素材。

## 9. 诚实边界（请一并转述给使用方）

- 本台只用于判断 **构图 / 尺寸 / 位置 / 素材选择**；
- 浏览器与引擎的**混合模式、发光、粒子行为并不一致**，颜色与光感只是近似；
- 因此本台的结论 **不能替代引擎内过目**，也 **不能** 作为质量状态（证据）升级的依据；
- 尺寸与位置之所以可信，是因为换算公式与几何来自数据包，与使用方引擎同源 —— **前提是导出器把几何填对**。
