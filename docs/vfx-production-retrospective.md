# 2D 特效失败复盘与生产门禁

本文把一次典型的“多阶段、定向传输、落点恢复”特效长链返工抽象为跨项目规范。它不是某个消费项目的历史记录，不包含角色、技能、卡牌编号、私有素材、截图或路径。目的不是保存聊天流水账，而是把失败症状还原成可预防的流程缺口，供任何 Godot 2D/伪 3D VFX 生产任务执行。

适用范围：单体/群体治疗、投射、命中、护盾、召唤、状态、法阵、拖尾与屏幕反馈；尤其适用于“技术检查不断通过，但成品持续被评价为廉价、混乱、不像设定”的任务。

## 1. 总结：真正失败的是生产顺序

长链返工通常不是某一个 Shader、粒子参数或贴图坏了，而是以下关键决策没有在昂贵实现前冻结：

1. 效果合同：谁施放、影响谁、何时结算、能否取消、目标消失后怎么办。
2. 视觉方向：图标与文本共同限定的母题、剪影、颜色、重心、前向轴和禁用元素。
3. 真实场景尺度：单位、棋盘、相机、背景、UI 和遮挡下到底多大、多亮、多快。
4. 导演节拍：准备、主动作、结算峰值、恢复、余韵之间怎样交接注意力。
5. 验收语言：怎样算“能读懂”“像目标材质”“可接入”，以及谁有权批准。

当这些问题没有先回答，团队会进入症状驱动的串行修补：边缘硬就加羽化，太暗就加辉光，运动像虫就加尾粒子，落点空就加花和圆环，效果太小就单独放大某层。每次修改都可能局部正确，却继续破坏整体比例、视觉主语和注意力路径。

专家工作流能节省的不是某个参数，而是提前拒绝不成立的方向。最昂贵的浪费，是在错误的低频剪影和主运动上堆高频细节。

### 1.1 如果一开始使用 Atlas 专家知识，哪些弯路可以避免

| Atlas 专家知识 | 本可提前暴露的问题 | 避免的返工 |
| --- | --- | --- |
| effect contract | S/T、锚点、结算、取消、距离策略不清 | 后期反复修选择流、固定时长、目标丢失和同步 |
| icon + text 双重约束 | 机制标签正确但视觉母题错误 | 从通用药丸/花/圆环方向整体推倒重来 |
| shape/motion/timing/finish 分工检索 | 把一个参考整体照搬，或混入多个互相冲突的参考 | 素材越加越多却没有统一视觉主语 |
| beat sheet 与 attention handoff | 全层同起同落、匀速直线、命中峰值模糊 | 逐轮修改速度、淡入淡出和亮度仍显得像 UI 动画 |
| temporal coherence + exposure sheet | 关键帧跨度过大、pivot 漂移、均匀 FPS | 交叉淡化、重影、固定单帧等补丁式处理 |
| texture 只承担 shape/finish | 一张图被要求同时负责形状、运动、材质、时序 | 资产和 Shader 职责纠缠，任何修改都牵动全局 |
| low-frequency first | 主剪影和路径尚未成立 | 用粒子、拖尾、花、辉光掩盖主体错误 |
| renderer probe + Compatibility fallback | UV、粒子 Shader、实例 uniform 等平台差异 | 完整组合完成后才发现核心层不可见或驱动异常 |
| real-scene Gallery | 隔离预览与正式棋盘尺度、背景、遮挡不同 | “预览里好看，接入后太小/太暗/偏位”的再校准 |
| explicit evidence states | 技术加载通过被误认为视觉和集成完成 | 过早交付、错误承诺、后续重新定义完成标准 |
| audited material roles | 搜索结果被误当作可复制资产或完整方案 | 许可返工、素材污染和风格拼贴 |
| checkpoint discipline | 每次续作重读长历史、重放大输出 | token 浪费、状态遗失、重复修已经否决的方向 |

这些知识只有被改写成“未通过就不得继续”的门禁才会真正省时。把文档当作建议、实现仍按直觉一路堆层，结果不会改变。

## 2. 失败链条：症状、根因、预防门禁

### 2.1 先做画面，后补语义

**典型症状**

- 效果看起来“像某种恢复”，但不像指定世界观、文本或图标。
- 原本应是有方向、有重量的主动作，被做成通用药丸、莲花、圆环或光点。
- 施法、传输、落点和恢复之间没有因果关系，只是多个漂亮元素依次出现。

**根因**

- 只读了机制标签，没有同时核对图标、文字、施法者、目标和真实场景。
- 把“治疗”“水”“神圣”等搜索词当成设计结论。
- 在没有禁用清单时，默认加入最常见的类型符号。

**为什么与预期不符**

用户期待的是“这个技能的唯一身份”，实现交付的却是“这个机制的通用图标语言”。机制正确不等于视觉身份正确。

**强制门禁**

- 先写效果合同和视觉方向卡。
- 列出 3–7 个明确禁用元素，例如：药瓶、莲花、圆环、十字、写实液滴、霓虹花瓣。
- 用户或美术负责人没有认可剪影、主色、重心和唯一主运动前，不生成正式素材，不搭多层场景。

### 2.2 用简单几何快速“交差”

**典型症状**

- 由几个圆、线、缩放和整体淡入淡出组成。
- 范围提示、命中补丁和装饰环大量重复。
- 画面能运行，却像调试占位、UI 动效或廉价手游模板。

**根因**

- 把原型阶段的几何占位当作美术终稿。
- 没有区分“玩法可读几何”和“世界观材质主体”。
- 认为添加数量能替代形状设计和材质行为。

**强制门禁**

- Primitive animatic 只用于验证锚点、路径、阶段和结算帧，默认不得直接升格为终稿。
- 若圆环不是范围信息或明确的视觉语言，必须删除。
- 在关闭粒子、Glow 和装饰层时，主形仍须成立。

### 2.3 没有导演节拍，素材只沿直线移动

**典型症状**

- 一张好素材像贴片一样从 A 平移到 B。
- 各层同时出现、同时消失，没有注意力交接。
- 命中峰值不清楚，结算时刻无法感知。
- 全程匀速，或所有阶段等时长。

**根因**

- 用资源清单代替 beat sheet。
- 没有先定义每阶段唯一视觉主语。
- spacing 与 timing 混为一谈。

**强制门禁**

每个效果先填写节拍表：

| 阶段 | 视觉主语 | 起止锚点 | 路径/形变 | easing | 峰值/停留 | 下一层如何承接 |
| --- | --- | --- | --- | --- | --- | --- |
| ANTICIPATE |  |  |  |  |  |  |
| CAST/RELEASE |  |  |  |  |  |  |
| TRAVEL/ACTIVE |  |  |  |  |  |  |
| IMPACT/SETTLE |  |  |  |  |  |  |
| RECOVER/CLEANUP |  |  |  |  |  |  |

任何阶段出现两个同等强度的主语，先删减或错峰；不要靠同时变亮制造“丰富”。

### 2.4 让序列帧承担过多职责

**典型症状**

- 少量差异巨大的关键帧硬拼成动画，轮廓跳动、重心漂移。
- 为掩盖跳帧而交叉淡化，产生重影和脏亮。
- 后来固定在某一帧解决抖动，却彻底失去动画生命。
- 整张图的 Alpha 同时控制形状、材质、局部溶解和生命周期。

**根因**

- 单套贴图同时承担 shape、motion、material、timing 和 finish。
- 没有帧间形变预算、稳定 pivot、曝光表和联系表。
- 把全局透明度当成材质变化。

**强制门禁**

- 一个短序列只表现一种原子形变。
- 相邻帧必须维持体积、重心、前向、纹理流向和 Alpha 边界连续。
- 单独记录逐帧时长，不默认均匀 FPS。
- 主体形状、内部流动、局部溶解、全局生命周期分别控制。
- 必须同时验收联系表、正常速度和慢放；静态单帧美观不算动画通过。

### 2.5 方向轴、pivot 与路径切线靠猜

**典型症状**

- 素材倒飞、横飞、转 90 度或前后颠倒。
- 非等比缩放后朝向继续偏移。
- 切图串入邻格、头尾留白不一致，导致路径锚点飘。

**根因**

- 默认素材“朝右”，没有检视实际 Alpha 轮廓。
- 只估计长轴，没有区分头尾。
- 每帧 pivot、画幅或相机不一致。

**强制门禁**

每个方向性素材保存：

- canonical forward，例如 `+X`；
- pivot 坐标与选择理由；
- tail landmark 与 leading-edge landmark；
- 每帧前向、置信度和歧义记录；
- 方向辅助图；
- 运行时旋转：`path_tangent_angle - native_forward_angle`。

Alpha 加权 PCA 只能辅助估计长轴，不能判断头尾；近圆形、卷涡和分叉主体必须人工按语义前缘核对。非等比缩放时先缩放轴向量，再计算最终角度。

### 2.6 尺度、透明度与层级各自调整

**典型症状**

- 施法过小，投射过大；或核心亮度盖住主体纹理。
- 所有边缘同样实、同样硬，像剪纸或贴片。
- 为解决太暗而无限叠加 additive Glow，最终过曝、偏色、丢形。

**根因**

- 没有总体强度包络和屏幕占比目标。
- 每层单独“看起来不错”，没有合成后校准。
- 把 Alpha 当作单一透明度，而非空间边界与时间包络的组合。

**强制门禁**

- 先规定各阶段屏幕占比、核心/主体/外辉光亮度比例和最大白场面积。
- 空间 Alpha：中心、边缘、尾部、溶解边界分别设计。
- 时间 Alpha：只负责进入、峰值、恢复和回收的总包络。
- Glow 关闭后仍能读形；亮底和暗底都能辨识。
- 调整亮度时先判断是底色、核心、边缘还是合成顺序的问题，不默认增加 Glow。

### 2.7 拖尾和粒子在目标渲染器上没有先做最小探针

**典型症状**

- `Line2D` 在某渲染器/纹理模式下不可见或 UV 行为异常。
- 拖尾细、长、偏移，像一条附加线而不是主体运动的延续。
- 粒子首帧闪出旧状态、在错误锚点喷发，或对象池复用时残留。

**根因**

- 在整套组合完成后才检查 renderer compatibility。
- 拖尾按世界路径采样，却没有与视觉头/尾锚点对齐。
- 粒子没有显式预热、清空和池化复位合同。

**强制门禁**

- 对 `Line2D`、自定义粒子 Shader、实例 uniform、屏幕纹理等风险特性先做单层最小探针。
- 探针必须使用目标 Godot 版本、目标渲染器和真实导入设置。
- 拖尾单独验证宽度曲线、纹理 UV、最大长度、采样频率、头尾对齐和消散。
- 粒子组件显式实现 `clear → reset transform → prewarm/emit → stop → recycle`，测试首播、连播、取消和对象池复用。

### 2.8 用装饰层修复主体不成立

**典型症状**

- 主运动像虫、光矛或小绿线，于是继续添加尾点、花、闪星和侧向装饰。
- 装饰元素重复、等距、沿直线排布，显得机械。
- 原本通用的恢复能力被某个技能专属符号永久污染。

**根因**

- 低频主体未获批准就进入高频细化。
- 没有把通用机制语言与技能风味拆层。
- 每次反馈只修表面形容词，没有回到剪影、路径和材质根因。

**强制门禁**

- 先只开主形和主运动；它们不成立时禁止添加粒子、花、符文或更多辉光。
- 每一层只能有一个职责，无法说清职责的层删除。
- 通用恢复核心与技能风味 Profile 分离：

```text
UniversalRecoveryCore
├─ upward/life-flow motion
├─ opaque colored body
├─ additive inner core
├─ settle peak and recovery envelope
└─ lifecycle/renderer fallback

SkillFlavorProfile (optional)
├─ petals / flowers
├─ water / mist
├─ runes / sigils
└─ palette and motif overrides
```

通用核心不能硬编码花、莲、圣徽、水纹等专属符号；风味层关闭后，机制仍须清晰。

### 2.9 距离自适应与结算时序处理太晚

**典型症状**

- 近距离一闪而过，远距离拖得过久；或固定时长导致速度剧烈变化。
- 拖尾在不同距离下过长或过短。
- 视觉命中与玩法结算错位。

**根因**

- 合同只写“从 S 到 T”，没有写距离策略。
- 视觉层自行猜测结算，不消费正式事件时间。

**强制门禁**

在 G0 合同中定义：

```text
travel_duration = clamp(distance / preferred_speed, min_readable_time, max_duration)
trail_length = clamp(distance * trail_ratio, min_trail, max_trail)
impact_time = committed_event_time or authored_normalized_impact
```

至少测试近、中、远三档；若机制要求固定抵达时刻，应明确接受速度变化，而不是实现后临时折中。

### 2.10 交互流和阶段类型没有先成为合同

**典型症状**

- 施法者/目标选择被错误状态锁住，预览与正式播放不一致。
- 某阶段误用了投射素材，或“施法动画”实际只播放首帧。
- 编辑器能修改数值但没有真正作用到运行实例。

**根因**

- 表现阶段、选择状态和 gameplay state 混在一起。
- 没有参数白名单、live adapter 与状态转换测试。

**强制门禁**

- 明确 `idle → select_source → select_target → preview → committed_play → cleanup` 状态图。
- 各阶段定义允许的节点类型和参数白名单。
- 编辑器修改必须通过与正式实例相同的配置入口生效，并可保存、重播、恢复默认。
- 视觉预览不得提交玩法状态；正式表现不得自行重算目标或数值。

### 2.11 编辑器和真实场景来得太晚

**典型症状**

- 隔离预览里合适，放进真实棋盘后太小、太暗、偏位或被 UI 遮挡。
- 为每个反馈改代码、运行、截图、再改一个参数，回合成本极高。
- 工具缺少阶段隔离、锚点辅助、导航、实时应用或参数持久化。

**根因**

- 把工具当成最终抛光，而不是生产基础设施。
- Gallery 与正式场景使用不同相机、缩放、配置和实例化路径。

**强制门禁**

复杂效果在正式制作前准备最小导演台：

- 嵌入真实背景、相机、单位、UI 和遮挡；
- 组合/单层/单阶段播放；
- 当前值与新增变化的明确区分；
- 锚点、路径、pivot、forward axis 与边界辅助线；
- 重播当前阶段；
- 参数白名单、实时应用、保存、撤销/恢复默认；
- 0.5×、1×、2× 与逐帧；
- 深色、亮色和真实背景；
- 近、中、远距离及 1/3/最大目标数。

### 2.12 把技术通过误报成视觉完成

**典型症状**

- 节点存在、Shader 编译、Alpha 非零、headless 退出码为 0，于是宣称“成品完成”。
- 有 GPU 截图，但没有人工确认真实速度、视觉身份和整体质量。
- 尚未接正式事件，只能在测试入口触发，却被描述为“已落地”。

**根因**

- 证据等级没有显式命名。
- 工程门禁、视觉门禁和集成门禁混为一谈。

**强制门禁**

只使用以下状态：

| 状态 | 必需证据 | 明确不代表 |
| --- | --- | --- |
| `generated_candidate` | 文件、导入、静态合同、基础加载通过 | 画面好看、目标 renderer 正确 |
| `gpu_validated` | 目标 renderer 真实截图/录像、日志、边界与异常分支 | 用户认可、正式接入 |
| `visual_approved` | 人工在真实场景按验收项明确批准 | gameplay/event 集成完成 |
| `project_integrated` | 正式事件、生命周期、回归矩阵、性能预算通过 | 未来所有平台无需再验收 |

禁止用“完成”“生产级”“真实落地”跨越中间状态。

## 3. 严格生产流程：G0–G9

以下门禁按顺序执行。上一个 Gate 未通过，不进入下一个昂贵阶段。

### G0 效果合同冻结

必填字段：

```yaml
effect_archetype: projectile | area | status | summon | screen_feedback | hybrid
gameplay_semantics: damage | heal | buff | debuff | movement | telegraph | cosmetic
source_anchor: actor/bone/socket/world/screen
target_anchor: unit/tile/path/world/screen
selection_flow: source/target/area/none
commit_event: formal event name or preview-only
settlement_frame: event time or normalized phase time
cancellable: true/false + boundary
target_missing_policy: cancel/freeze/continue-to-last-position/retarget
distance_policy: fixed-duration/fixed-speed/clamped-adaptive
max_concurrency: integer
renderer_and_version: exact Godot version + renderer
performance_budget: particles/draw calls/texture memory/instances
fallback: no-glow/no-custom-particles/reduced-density
```

**通过条件**：语义、锚点、时序、异常分支和预算无待猜字段。

### G1 视觉方向冻结

输出一页方向卡：

- 图标/文本共同推导出的母题；
- 低频剪影与视觉重心；
- 唯一主运动；
- 主色、辅色、核心色及最大亮度；
- 世界空间/屏幕空间归属；
- 屏幕占比与真实单位比例；
- 前向轴、pivot、头尾；
- 允许元素与禁止元素；
- 2–4 个 Atlas 参考，各自只负责 shape/motion/timing/finish 中一种证据。

**通过条件**：审阅者能仅凭方向卡区分该效果与同机制的通用模板。

### G2 真实场景 Primitive Animatic

只用 `ColorRect/Polygon2D/Line2D`、简单遮罩和 Tween，在真实棋盘/场景中验证：

- 谁施放、飞向哪里、何时结算、影响谁、多久结束；
- 近中远距离；
- 单目标、多目标；
- 0.5×、1×、2×；
- 相机、遮挡、UI 和单位尺度。

**禁止**：正式生图、复杂 Shader、大量粒子、装饰符号。

**通过条件**：第一次人工 Gate 明确认可语义、路径、节拍和尺度。

### G3 原子资产生产

每项资产只承担一种职责，并记录：

- asset ID、role、source/license/hash；
- canvas、pivot、native forward、scale；
- Alpha 类型与边缘检查；
- 帧数、帧序、逐帧曝光时长；
- 相邻形变、体积、重心和方向连续性；
- 接受/拒绝理由。

**通过条件**：联系表、正常速度、慢放均通过；不存在画入 RGB 的棋盘格、假透明、邻格串入或硬彩边。

### G4 低频主体 Pass

只实现：主剪影、路径、起止尺度、easing、结算峰值、回收。

关闭 Glow、粒子和风味层进行审核。若主体像虫、贴片、光矛、UI 图标或无重量的线条，此 Gate 失败，必须回到 G1/G2/G3，不能进入细化。

### G5 材质 Pass

分别实现：

- 内部流动或体积变化；
- 空间羽化与局部溶解；
- 核心、主体、外辉光的亮度关系；
- 总体进入/峰值/恢复包络；
- 目标 renderer fallback。

先做单层 renderer probe，再组合。整体 Alpha 不得代替局部材质演变。

### G6 中高频细节 Pass

按职责逐一加入 core、halo、trail、motes、debris、flavor。每加入一层都回答：

1. 它补充了哪种信息？
2. 删除后语义、材质或层次是否确实变差？
3. 是否与现有层抢视觉主语？
4. 是否属于通用核心，还是可选风味？

不能回答或没有可见收益的层删除。

### G7 参数范围选择与 A/B/C 对照

不要每轮只改一个参数并重新截图。一次生成可对照的参数板：

- A：保守；
- B：目标；
- C：强调。

优先比较尺寸、速度、拖尾宽度/长度、主体不透明度、核心强度、粒子密度。保持其余变量不变，在同一真实场景、同一帧位和同一播放速度下比较。选定范围后再微调，避免串行“更亮一点/更慢一点”的 token 与构建浪费。

### G8 GPU 与异常矩阵

至少覆盖：

| 维度 | 必测值 |
| --- | --- |
| 背景 | 暗、亮、真实场景、Glow off |
| 距离 | 近、中、远 |
| 目标 | 1、3、最大设计数量 |
| 速度 | 0.5×、1×、2×、逐帧/慢放 |
| 生命周期 | 首次、连续重播、取消、目标消失、对象池复用 |
| 并发 | 1、常见峰值、最大预算 |
| 渲染 | 目标 Godot 版本/renderer、降级路径 |
| 证据 | 正常速度录像、关键帧截图、联系表、错误日志、性能数值 |

**通过条件**：升级为 `gpu_validated`；仍不可称视觉批准。

### G9 人工批准与正式集成

人工在真实场景确认：

- 能立即读出施法者、目标、结算时刻和结果类型；
- 视觉身份与方向卡一致；
- 主体材质、重量、速度和收尾可信；
- 不依赖过曝、噪点或专属装饰才能成立；
- 不遮挡关键 UI 和玩法信息。

批准后升级为 `visual_approved`，再接正式 Event/ViewModel、对象池、取消与回收路径。正式入口回归通过后才升级为 `project_integrated`。

## 4. 反馈处理协议：先归因，后改参数

收到“太亮、太暗、像虫、像贴片、太小、太快、很乱、不高级”等反馈时，不应直接把形容词映射为一个参数。先分类：

1. **身份问题**：母题/符号错误 → 回 G1。
2. **剪影问题**：主形、比例、屏幕占比错误 → 回 G1/G3/G4。
3. **运动问题**：路径、easing、方向、距离策略错误 → 回 G2/G4。
4. **时序问题**：峰值、停留、层交接错误 → 回 G2/G4。
5. **材质问题**：Alpha、流动、溶解、亮度层级错误 → 回 G5。
6. **细节问题**：粒子、拖尾、装饰密度错误 → 留在 G6/G7。
7. **技术问题**：renderer、UV、导入、生命周期、首帧闪 → 最小探针后修 G3/G5/G8。
8. **集成问题**：锚点、正式事件、状态、UI/遮挡 → 回 G0/G2/G9。

修改前记录：反馈原句、归因类别、将改变的单一假设、保持不变的变量、验证画面。连续两轮同类反馈仍未改善，应停止局部调参，退回上一个 Gate 重审结构。

## 5. 导演台与参数系统的最低合同

复杂效果的预览工具是生产设施，不是完成后的附属品。最低要求：

- 与正式实例共享同一 `.tres/Resource` 配置和实例化路径；
- 支持阶段、层、目标数、距离、速度、背景和 Glow 的组合切换；
- 只暴露该阶段允许的参数，防止错误类型跨层污染；
- 参数修改实时作用于当前实例，可重播当前阶段；
- 明确区分当前值、临时增量、已保存值和默认值；
- 保存格式带 schema/version，无法应用的字段显式报错；
- 锚点、边界、路径、pivot、forward axis 可视化；
- 可导出带参数摘要的截图/录像，便于 A/B/C 对照；
- 隔离预览与真实场景预览一键切换；
- 预览绝不提交 gameplay state。

如果导演台显示的值与正式实例不同，先修工具链，不继续美术调参。

## 6. Token、日志与跨会话续作规范

长链 VFX 任务很容易把资源消耗在重复读历史、重复跑全量测试和单参数截图上。每个 Gate 完成后保存一个小型项目内 checkpoint：

```yaml
goal: 当前明确目标
quality_state: generated_candidate/gpu_validated/visual_approved/project_integrated
contract_version: 合同版本或哈希
direction_version: 方向卡版本或哈希
selected_assets: IDs + hashes + licenses
current_parameters: 配置路径或 manifest
verified_evidence: 命令、renderer、截图/录像路径、结果
human_decisions: 已批准与已否决项
unresolved_issues: 按优先级列出
next_safe_action: 单一下一步
```

执行纪律：

- 大索引本地筛选，只输出候选 ID、证据、许可、风险。
- 大日志写文件，只回传退出状态、错误行、有限尾部和证据路径。
- 图片用图像通道查看，不把 base64/data URL 打进文本。
- 多候选优先联系表或 A/B/C 板；身份、边缘、Alpha 和方向仍需查看原图。
- 不为每个单参数改动都提交、全量构建和完整 GPU 录制；按一个可审查假设成组修改。
- 重复传输失败后停止盲目重试，先落盘 checkpoint，再报告错误；不要未经证据归因网络、上下文或模型。
- 新任务仍须重新读取其必需规则；checkpoint 只替代历史回放，不替代当前约束。

## 7. 独立游戏生产级 Definition of Done

只有同时满足以下条件，才能称为可真实落地的独立游戏级特效：

- 效果合同、视觉方向卡、节拍表、资产 manifest 和性能预算齐全。
- 图标/文本/机制/真实场景语义一致，禁用元素未混入。
- 关闭 Glow、粒子和风味层时低频主体仍成立。
- 正常速度、慢放、联系表均无跳帧、漂移、首帧闪、重影和 Alpha 突变。
- 近中远、单/多目标、取消、目标消失、连续重播、对象池复用与最大并发通过。
- 在目标 Godot 版本和 renderer 上真实 GPU 验证，fallback 可用。
- 暗底、亮底、真实场景、Glow off 均可读，不遮挡玩法信息。
- 通用核心与技能风味解耦，专属符号不是机制成立的必要条件。
- 人工明确批准真实场景结果。
- 正式 Event/ViewModel 和生命周期路径接入，不由表现层重算玩法结果。
- 所有来源、许可、哈希、生成记录和拒绝原因可追溯。
- 交付说明准确区分四级状态，没有把技术通过写成视觉完成。

若任一项未满足，应准确报告停留状态、缺失证据和下一 Gate，而不是继续用装饰层掩盖结构问题。
