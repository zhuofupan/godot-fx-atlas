Human in the loop

先把方案、选材、摆位定下来，再进引擎。

原来的闭环是「写实现 → 进引擎 → 截图 → 人看 → 返工」—— 把最贵的媒介放在了最前面。 这里把三件事挪到浏览器里：① 方案（极性 / 锚点 / 唯一母题 / 唯一运动 / 目标色）、 ② 选材（在真实读数尺寸上比对）、③ 摆位（大小 / 偏移，直接拖动）。 人认可之后才写进引擎。

这不是引擎验收。浏览器与引擎的混合、发光、粒子行为并不一致。本台只用于判断 构图 / 尺寸 / 位置 / 素材选择；结论不能替代引擎内过目，也不能作为质量状态的证据。 尺寸与位置用的是数据包里的几何（卡面 / 棋格 / 锚点 / 归一系数），与使用方工程一致。

还没有导入任何数据包

本工作台是项目无关的：它不认识任何具体工程，全部几何与素材都由数据包注入。数据包不进 git。

  1. 在使用方工程里跑它的导出器，产出一个数据包：
    project-data/<bundle-id>/bundle.json
  2. 回到本仓库执行 npm run build:workbench（`npm run build` 也会带上）。
  3. 用 npm run dev 打开本页。

数据包格式见 docs/workbench.md；project-data/ 已在 .gitignore 中。

交回工程

改了任何设置都会自动写回磁盘（project-data/<bundle>/workbench-state.json）， 手绘会写成 drawings/<条目>.png —— 你不需要下载任何文件。 使用方的 AI 直接读磁盘就能知道你在网页上设了什么、画了什么。 下面这份内容与写回磁盘的完全一致，需要手工转述时可以复制。
